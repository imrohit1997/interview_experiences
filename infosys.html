JVM & Memory Management (10:15:28)

2. Can you brief about the JVM architecture? What is it, why do we use it, and why do we tune it?

JVM Architecture: The JVM (Java Virtual Machine) is the engine that provides the runtime environment to drive the Java Code or applications. It converts Java bytecode into machine language. Key components include the Classloader, Memory Area (Heap, Stack, Method Area), Execution Engine (Interpreter, JIT Compiler), and JNI (Java Native Interface).

Why Tune: We tune the JVM to optimize application performance, manage memory usage, reduce latency (like Garbage Collection pauses), and improve throughput.

3. What is the difference between JDK, JRE, and JVM?
  • JVM (Java Virtual Machine): An abstract machine that executes Java bytecode.
  • JRE (Java Runtime Environment): Contains the JVM plus Java binaries and other classes to execute programs successfully. (JRE = JVM + Library Classes)
  • JDK (Java Development Kit): A software development environment used to develop Java applications. (JDK = JRE + Development Tools like javac, java, etc.)
4. What is the difference between Heap and Stack memory?
  • Heap Space: Used for dynamic memory allocation of Java objects and JRE classes at runtime. Objects created via the new keyword are stored here. It's accessible globally.
  • Stack Memory: Used for static memory allocation and execution of a thread. It contains primitive values specific to a method and references to objects that are in the heap. It's accessed in LIFO order and is specific to each thread.
5. What are the main causes of performance issues like memory problems, network issues, or slowness in Java applications?
  • Memory Leaks: Objects being referenced when no longer needed, preventing Garbage Collection.
  • Improper GC Tuning: Frequent Full GC pauses (Stop-The-World) causing slowness.
  • Thread Deadlocks/Contention: Threads blocked waiting for resources.
  • Inefficient DB Queries / Network Calls: High latency in external communications, lack of connection pooling.

Garbage Collection (10:21:50)

6. Why should we be very cautious when working with the Java Garbage Collector, and can we tune it?

Why cautious: Garbage Collection is an automatic process, but it introduces Stop-The-World (STW) events where application threads are paused to reclaim memory. If GC happens too frequently or takes too long, it severely impacts application latency and throughput.

Tuning: Yes, we can tune the GC by setting heap sizes (-Xms, -Xmx), choosing the right GC algorithm (e.g., -XX:+UseG1GC), and adjusting specific parameters like new generation size or max pause time target.

7. What are the types of Garbage Collectors? Is G1GC different from the default GC? What are the GC enhancements between Java 8 and Java 11?
  • Types: Serial GC, Parallel GC, CMS (Concurrent Mark Sweep) GC, G1 (Garbage First) GC, ZGC, Shenandoah.
  • G1GC vs Others: G1GC is designed for multi-processor machines with large memory. It divides the heap into regions and prioritizes collecting regions with the most garbage, aiming to meet predictable pause-time goals.
  • Java 8 vs Java 11: In Java 8, Parallel GC was the default. In Java 9 and thus Java 11, G1GC became the default Garbage Collector. Java 11 also introduced the Epsilon GC (No-Op GC) and ZGC (experimental low-latency GC).
8. What is STW (Stop-The-World)?

STW refers to the pause in the application execution where the JVM suspends all application threads to safely execute Garbage Collection (like marking live objects or compacting memory). During this time, the application is entirely unresponsive.

Multithreading & Concurrency (10:30:32)

9. Why should we use the Executor Framework instead of manually creating threads?
  • Resource Management: Creating and destroying a new thread for every task is expensive. The Executor Framework uses thread pools to reuse existing threads.
  • Control: It allows controlling the number of active threads, preventing OutOfMemoryError from spawning too many threads.
  • Simplified Concurrency: Decouples task submission from task execution. Provides features like task queuing and scheduling.
10. What is the difference between CompletableFuture and the Executor Framework? Why use CompletableFuture?
  • Executor Framework (Futures): Submitting a task returns a Future. To get the result, you must call future.get(), which is blocking. You cannot easily chain multiple futures together.
  • CompletableFuture: Introduced in Java 8, it implements both Future and CompletionStage. It allows you to build complex asynchronous pipelines by chaining callbacks (thenApply, thenAccept) that execute non-blockingly when the computation finishes.
11. If a thread is stuck in a blocked state in production, how would you troubleshoot and resolve it?

Troubleshooting:

  • Take a Thread Dump using tools like jstack, jcmd, or VisualVM.
  • Analyze the thread dump to identify the blocked thread and see exactly which resource or monitor lock it is waiting for, and which thread holds that lock (finding deadlocks).

Resolution: Analyze the code to fix locking order (to prevent deadlocks), add timeouts to external calls, or increase connection pool sizes if it's waiting on a connection.

Spring Boot & Production Troubleshooting (10:36:53)

12. What does the @SpringBootApplication annotation do?

It's a composite annotation that combines three key annotations:

  • @Configuration: Marks the class as a source of bean definitions.
  • @EnableAutoConfiguration: Enables Spring Boot's auto-configuration mechanism to automatically configure beans based on dependencies in the classpath.
  • @ComponentScan: Scans the package (and sub-packages) for Spring components (@Component, @Service, etc.).
13. If the startup of a Spring Boot application takes 5+ minutes, what steps would you take to debug and resolve it?
  • Analyze Startup Logs: Enable debug logging to identify which beans take the longest to initialize.
  • Lazy Initialization: Enable spring.main.lazy-initialization=true so beans are only created when needed, rather than all at startup.
  • Database Connections: Check if Flyway/Liquibase scripts are taking too long, or if JPA entity scanning is inefficient.
  • Network/External APIs: Ensure the app isn't hanging while waiting for a timeout from an external service during startup.
  • Component Scan: Narrow down the @ComponentScan base packages to avoid scanning unnecessary classes.
14. If an API in production suddenly spikes in latency from 300ms to 3 seconds, how do you troubleshoot it?
  • APM Tools: Check Application Performance Monitoring tools (like New Relic, Datadog, AppDynamics) to isolate the bottleneck (is it DB, Network, or Code?).
  • Logs & Traces: Check application logs for exceptions. Use distributed tracing (Zipkin/Jaeger) to see which microservice or component is slow.
  • Database: Check if database queries are suddenly slow (missing indexes, database locks, slow queries log).
  • Infrastructure: Check CPU, memory, and JVM metrics (is there a sudden GC pause/memory leak?) or network issues.

Coding Assessment (10:43:22)

15. Write a Java 8/11 program to take an array of decimals, sort them in reverse order, and then replace the middle elements. For an array of 10 elements, replace the 5th and 6th elements with the 1st and 10th elements, respectively.
import java.util.Arrays;
import java.util.Collections;

public class ArrayManipulation {
    public static void main(String[] args) {
        Double[] decimals = { 1.2, 5.5, 3.4, 9.1, 2.8, 7.6, 4.4, 8.9, 6.3, 0.5 };
        
        // 1. Sort in reverse order
        Arrays.sort(decimals, Collections.reverseOrder());
        System.out.println("Reverse Sorted: " + Arrays.toString(decimals));
        
        // Array length is 10. Indices 0 to 9.
        // 2. Replace middle elements
        // 5th element (index 4) replaced by 1st (index 0)
        // 6th element (index 5) replaced by 10th (index 9)
        if (decimals.length == 10) {
            decimals[4] = decimals[0];
            decimals[5] = decimals[9];
        }
        
        System.out.println("Modified Array: " + Arrays.toString(decimals));
    }
}
